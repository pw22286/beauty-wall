### 1. 交互流程设计

#### A. 侧边栏底部工具栏 (The Sidebar Toolbar)
在左侧“来源列表”的底部，添加一个小工具栏（这是 macOS 的标准做法）。

*   **UI 元素**：
    *   `+` (添加按钮)
    *   `-` (删除按钮)
    *   `...` (更多操作，可选，如：复制预设、重命名)
*   **交互逻辑**：
    1.  **点击 `+` 按钮**：
        *   **不要**直接添加一个空白项。
        *   **应该**弹出一个小菜单（Context Menu），列出支持的平台。
        *   菜单内容：
            *   `添加 Wallhaven 来源`
            *   `添加 Unsplash 来源`
            *   `添加 本地文件夹 来源` (未来功能)
    2.  **点击 `-` 按钮**：
        *   删除当前选中的来源配置（建议弹窗二次确认：“确定要删除‘我的赛博朋克配置’吗？”）。

#### B. 新建来源后的状态 (Creation State)
当用户选择了“添加 Wallhaven 来源”后：

1.  **列表变化**：左侧列表中新增一行。
2.  **默认命名**：系统自动给一个名字，例如 `Wallhaven 1` 或 `New Wallhaven`。
3.  **自动聚焦重命名**：新建的一瞬间，左侧列表中的名字处于**“可编辑状态”**（高亮选中），方便用户立刻改名为有意义的名字，比如 `二次元 SFW` 或 `4K 风景`。
4.  **右侧联动**：右侧详情页立即显示 Wallhaven 对应的参数表单。

#### C. 右侧详情页的动态渲染 (Dynamic Detail Pane)
右侧区域的内容需要根据左侧选中的 Item 类型发生变化。

*   **顶部标题区**：
    *   显示当前配置的**名称**（可在这里再次编辑）。
    *   显示**图标**（Wallhaven 的 Logo 或 Unsplash 的 Logo），明确当前配置的类型。
*   **参数区**：
    *   **如果左侧选的是 Wallhaven 类型**：显示你截图中的“关键词”、“纯度”、“分类”、“分辨率”等。
    *   **如果左侧选的是 Unsplash 类型**：显示“Collection ID”、“关键词”、“方向（横/竖）”等 Unsplash 特有的参数。

#### D. 激活/切换来源 (Activation)
这是最关键的一点：**“编辑”不等于“使用”**。

*   **编辑**：点击左侧列表的某一行（变蓝），右侧显示参数供你修改。
*   **使用（激活）**：
    *   **方案一（单选模式 - MVP 推荐）**：
        *   在左侧列表的每一行右边，保留你现在的**对勾（√）**设计。
        *   用户点击哪一行的对勾（或者双击该行），哪一行就变成“当前生效的壁纸源”。
        *   **逻辑**：互斥单选（Radio Button Logic）。
    *   **方案二（多选混合模式 - 进阶）**：
        *   每一行前面放一个**复选框（Checkbox）**。
        *   用户可以勾选 `[x] 赛博朋克` 和 `[x] 自然风景`。
        *   **逻辑**：软件在刷新壁纸时，先随机从勾选的配置中选一个配置，再用该配置去请求图片。

### 2. 数据结构设计建议（Model 层）

为了支持这种“多来源管理”，你的数据模型需要调整。不要把配置写死成 `app.config.wallhaven`。

建议结构（伪代码）：

```swift
// 1. 定义来源类型枚举
enum WallpaperSourceType: String, Codable {
    case wallhaven
    case unsplash
    case local
}

// 2. 定义一个通用的配置协议或基类
struct SourceConfig: Identifiable, Codable {
    var id: UUID = UUID()
    var name: String          // 用户自定义的名字，如 "我的工作模式"
    var type: WallpaperSourceType
    var isEnabled: Bool       // 是否被选中/激活
  
    // 具体参数（可以用字典，或者关联枚举，或者独立的属性）
    // 简单做法：把所有平台的参数都放这里，根据 type 决定用哪些
    var wallhavenParams: WallhavenParams?
    var unsplashParams: UnsplashParams?
}

struct WallhavenParams: Codable {
    var keywords: String
    var purity: String
    var minResolution: String
    // ...
}

// 3. App 的总状态
class AppState: ObservableObject {
    // 这里存储一个数组，而不是单个对象
    @Published var sources: [SourceConfig] = []
  
    // 记录当前激活的是哪个 ID
    @Published var activeSourceId: UUID? 
}
```

### 3. 这种设计的优势

1.  **无限扩展**：用户可以存 10 个不同的 Wallhaven 配置（一个看妹子，一个看风景，一个看高达），只需一键切换，不需要每次都去改关键词。
2.  **清晰直观**：左侧列表一目了然，知道自己有哪些“频道”。
3.  **符合直觉**：这就像浏览器的“书签”或者播放器的“歌单”一样，用户不需要学习成本。
